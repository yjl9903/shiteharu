# 资源、重建与交付

准备资源、修改路径或执行构建与交付时参考本文。全仓库通用规则见 [AGENTS.md](../AGENTS.md)。

## 自包含与可复现性

- 工作区必须 self-contained（自包含）：换一个检出位置或一台机器后，应能依据仓库内的配置、资料与说明准备输入并重建结果。自包含以整个仓库为边界，单片工程可以通过相对路径使用仓库共享资源。
- 不得在未说明的前提下依赖本机路径、系统字体、其他检出目录、全局安装包、已有缓存或工作区外的手工文件。“本机已经存在”不构成依赖说明。
- 可分发的必要源码、配置、人工校对结果、设计数据和资源来源记录应纳入版本管理。大体积媒体、受许可限制的资源、凭据及可重建缓存可以不入库，但必须有明确的准备或重建方式；被 Git 忽略不等于可以省略依赖说明。
- 未入库的必要资源须在工程 README 或资源清单中记录来源、版本或资源标识、仓库内预期相对路径、获取或生成步骤，以及必要的授权条件。原片、字体等会影响结果的输入应记录校验值，以便确认重建使用了同一份资源。
- 工具与运行环境须记录依赖清单、安装方式和影响结果的版本或构建特性，例如 FFmpeg 的 libass 支持。新增依赖时同步更新相应说明，不隐式借用其他工程的虚拟环境。
- 转写、模型生成等不保证重复运行得到相同结果的阶段，应保留原始输出、已确认的人工结果和必要参数，后续构建从明确保存的输入开始，不依赖再次调用服务来还原既有交付。
- 缺少必要输入时明确报错并指出准备步骤，不静默换用系统字体、其他视频或旧缓存。无法获取的资源或无法复现的环节应明确记录限制；影响交付时向用户确认替代方案。
- 缓存应能从已声明的输入重新生成，不能成为唯一数据源。工程 README 应说明从准备素材到构建、预览、渲染、打包的命令，以及哪些阶段尚未完成。

## 路径与本地资源

- 配置、代码、文档和生成的审阅/预览数据不得保存本机用户目录、系统字体安装目录或其他机器特有的绝对路径。
- 工程配置中的文件路径以对应的 `production/<工程>/` 为基准，包括子目录内配置的路径字段；共享字体和原片分别通过 `../../fonts/`、`../../downloads/` 引用。文档链接按文档所在位置解析，命令示例须说明工作目录。
- 脚本通过自身位置推导工程或仓库目录，不依赖调用者的当前工作目录。运行时可解析为绝对路径，写回配置、报告或可共享的生成数据前须转换为约定基准下的相对路径。
- 共享工具通过显式配置接收工程输入，不扫描并猜测要使用的原片、成片或字体。工作区外资源须先按说明准备到约定目录，再由相对配置引用。
- 本机字体副本放在被忽略的 `fonts/local/`，记录合法获取方式、所需文件及版本；凭据放在被忽略的环境配置中，只提交变量名和不含秘密的示例。二者均不纳入交付包。
- 不得用指向本机绝对路径或工作区外资源的软链接绕过上述约定。

## 验证与交付

- 按修改影响验证：路径与配置修改运行仓库根目录的 `python3 scripts/check_paths.py`；代码修改运行对应模块的必要测试；字幕或演出修改检查代表画面、时间边界、缺字与重叠，并在交付前完成相应渲染核验。
- 生成文件不能替代可编辑源。打包时保留相对目录关系、必要源码与配置、许可和重建说明，并列明未包含资源的准备步骤。
- 报告实际完成的检查和仍待核验的内容，不将自动转写、采样观察或成功运行脚本等同于人工字幕及全片演出验收。
