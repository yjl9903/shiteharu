# 目录与模块职责

本仓库按制作流程组织数据：原始素材与转写提供依据，工作稿和设计保存当前制作内容，审阅记录保存判断与证据，交付目录保存生成结果，缓存保存可丢弃的运行数据。新增文件时先确定它在流程中的职责，再选择目录。全仓库通用规则见 [AGENTS.md](../AGENTS.md)。

手工维护的工具、工程和设计配置统一使用 TOML；事件设计使用 `[[events]]`，对照片段使用 `[[clips]]`。生成报告、运行快照、第三方 API 数据和规范 JSON 时间轴按其数据格式保留，不作为配置格式的替代入口。

## 仓库共享资源与工具

公共工具负责通用操作，单片工程保存内容与制作决策。工程不保留制作工具实现、启动脚本或兼容入口；字体选择、提案依据与重点样例属于工程数据。

以下路径相对仓库根目录。按实际需要建立目录，不要求新工程预建空目录。

| 路径 | 职责 |
| --- | --- |
| `AGENTS.md` | 全仓库通用规则与按任务查阅的资料索引。 |
| `docs/` | 跨工程约定与操作说明；单片细节仍留在对应工程。 |
| `docs/reproducibility.md` | 制作过程中的资源、路径、依赖维护、验证与交付要求。 |
| `docs/migration.md` | 具体迁移恢复步骤、资源清单、环境准备、原片恢复与验证记录。 |
| `README.md` | shiteharu 资料、视频索引、整体制作状态和工程入口。单片操作细节放到工程 README。 |
| `pyproject.toml`、`uv.lock`、`.python-version` | 全仓库 Python 依赖、锁定版本和解释器版本；统一通过 uv 管理根目录 `.venv/`。 |
| `production/<工程>/` | 单个视频的独立制作工程；工程清单与状态见仓库 README。保存该片的内容、配置、研究数据和交付结果。 |
| `downloads/` | 原片及下载素材，通常不入库；来源与准备方法保存在对应工程中，不修改原片。 |
| `fonts/` | 正式使用的共享字体、许可、来源及派生字形记录；来源索引为 `fonts/SOURCES.md`。 |
| `fonts/local-fonts.toml` | 不分发的实际制作字体清单与准备来源。 |
| `fonts/local/` | 不随仓库分发的本机字体副本；必须有准备说明，不作为隐藏依赖。 |
| `tools/<工具>/` | 跨工程使用的制作辅助工具，各自维护实现、说明与测试；Python 依赖由仓库根目录统一管理。 |
| `tools/forge/` | 公共字幕构建、字体准备、视频渲染、对照与研究算法；工程通过 `forge.toml` 和数据声明制作决策。 |
| `tools/loupe/` | 公共字幕与字体审阅工具，负责播放器、搜索、画面对照、同步、媒体探测和字体覆盖检查；通过工程配置读取输入，不导入单片 Python 模块。 |
| `tools/captions/` | Forge 与 Loupe 共用的文字分段和字体角色解析；不读取工程配置、不执行渲染或研究流程。 |
| `.githooks/pre-commit` | 随仓库保存的提交前路径检查；新检出通过 `core.hooksPath` 启用，检查暂存内容中的本机绝对路径及绝对软链接。 |
| `.cache/` | 仓库级可重建缓存；Loupe 快照放在 `.cache/loupe/`。不保存唯一的人工成果，不纳入交付。 |
| `.env`、`.venv/` 等被忽略的环境文件或目录 | 本地凭据与运行环境；准备方法由相应文档和依赖清单描述。 |

## 单片工程

以下路径相对 `production/<工程>/`。工作稿、设计与研究依据保留可编辑内容；导出文件的修改应回到对应源数据，再重新生成。

| 路径 | 职责 |
| --- | --- |
| `README.md` | 原片来源、制作状态、编辑入口、依赖准备、重建命令和交付说明。 |
| `description.md` | 该片的语境、术语、翻译原则与内容决策。 |
| `session.toml`、`source.info.json` | 制作会话、原片标识与媒体元数据；按工程实际使用维护。 |
| `forge.toml`、`preview.toml`、`bilipack.toml` | 审阅工具或交付工具的工程配置；不承载工具实现。 |
| `transcript/raw/` | 原始转写与检查点，保留为参考依据，不直接改写为人工终稿。 |
| `transcript/work/` | 日文人工校对及时间轴工作数据。 |
| `translation/work/` | 中文翻译与润色工作数据；与设计数据共同构成字幕构建输入。 |
| `patches/` | 可应用的转写、翻译修订及逐项依据；候选建议须与已应用修改区分。检查范围和整体结论放在 `review/`。 |
| `design/` | 字体角色、默认样式、逐条演出、补充字幕与对照片段配置；保存当前制作参数，格式说明放在 `SCHEMA.md`。审阅结论放在 `review/`。 |
| `research/` | 该片的研究依据、候选资源、实验数据与提案；获采纳的结果须明确应用到正式配置或资源，日常构建不隐式依赖实验缓存。 |
| `clips/`、`audio/` | 片段校对材料与提取音频；保留片段配置、转写结果及校对依据，媒体从原片提取。 |
| `frames/` | 原画取证帧、逐事件合成图与成片采样；保存对应取帧参数。被审阅记录引用的历史画面须保留，不能仅因属于派生文件就删除唯一副本。 |
| `output/` | rajio 的标准字幕导出，不作为最终演出数据的手工编辑入口。 |
| `review/` | 内容、时序、排版和交付的审阅结论、疑点、用户修订依据及检查报告。记录所检查的版本和覆盖范围，不另存一套字幕工作稿。 |
| `review/comparisons/` | 供审阅者查看的原片／译文对照视频及截图；由 Forge 按 `design/clips.toml` 生成，历史局部样片也归这里。媒体另行备份。 |
| `deliverables/` | 当前对外交付的 ASS/SRT、完整成片、预览与封面；修改回到工作数据或设计源后重新生成。放在这里不代表已通过验收，状态以工程 README 和核验记录为准。 |
| `.cache/` | 本工程可丢弃的渲染字体缓存、临时墨迹与日志，区别于仓库级共享工具缓存；不能保存唯一的人工成果或审阅证据。 |

目录职责与 Git 跟踪分别管理：被忽略的媒体仍可能需要备份。具体留存与恢复方式见 [迁移指南](migration.md)。

## 制作数据流与读写方

| 阶段 | 读取 | 写入者与输出 | 后续使用者 |
| --- | --- | --- | --- |
| 转写与校对 | 原片、音频、原始转写 | 转写服务与 rajio 保存 `transcript/raw/`；制作者通过校对补丁维护 `transcript/work/` | 翻译与校对者 |
| 翻译与演出 | 日文工作稿、原画证据、研究结论 | 制作者维护 `translation/work/`、`design/`；修订依据留在 `patches/`、`review/` | Forge；Loupe 读取工作稿与设计展示信息 |
| 标准字幕导出 | 中日工作稿 | rajio 写入 `output/` | 文字检查与标准字幕使用者 |
| 演出字幕构建 | 工作稿、设计、字体配置 | Forge `build` 写入 `deliverables/` 的 ASS/SRT | 视频渲染与局部对照 |
| 视频渲染 | 原片、工作稿、设计、字体 | Forge `render` 构建字幕并渲染至 `deliverables/` | Loupe、审阅者与投稿工具 |
| 局部对照 | 原片、已构建 ASS、字体缓存、选段配置 | Forge `compare-clips` 写入 `review/comparisons/*.mp4`；`compare-stills` 从 MP4 中点取 JPG | 人或代理查看并将结论记入 `review/` |
| 取证与检查 | 原片、字幕、设计、字体 | Forge 取帧到 `frames/`，报告到 `review/`，临时墨迹到 `.cache/` | 制作者判断；自动候选不等于验收 |
| 审阅与发布 | 工程配置显式指定的文件 | Loupe 消费原片、成片和工作稿，运行缓存写入仓库 `.cache/loupe/`；投稿工具读取成片及封面 | 审阅者与发布平台 |

对照生成命令不会先构建字幕或准备字体，须在运行前执行 `build`、`fonts-prepare`。截图读取已有对照视频；工作稿、视频和截图不会自动同步。重新生成会覆盖同名文件，保留历史证据时先备份。
