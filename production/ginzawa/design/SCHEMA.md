# Editable design contract

Every visible source-caption unit needs its own explicit event record, including ordinary captions. Record `source_style`, `source_boxes`, `timing_status`, and a `evidence` list of relative screenshot/clip paths. `timing_status = "frame-confirmed"` is permitted only after inspecting the adjacent actual source frames at its start and end. Frame images are local ignored evidence; preserve their relative indices and reproducible capture inputs.

For this project, normal Chinese captions preferentially sit close above the existing Japanese in the lower caption area. Evaluate a readable lower placement first, including modest font reduction and scene-specific line breaks; use top placement when the actual lower composition cannot accommodate it without obscuring meaningful content. Never obscure the source Japanese. Keep intentional emphasis, typeface category and movement, but do not mechanically copy oversized source lettering or preserve a fixed size ratio when the added Chinese hides the subject. Judge faces and expressions, objects being discussed, signage, scenery, concurrent annotations and movement across the event together. Conservative rectangles and font sizes only identify candidates; actual composited frames decide. Explicit user-directed positions remain authoritative. Record scene-specific reasons for exceptions. Do not apply automatic animation to ordinary captions.

User-confirmed opening corrections take precedence over a generic top-placement heuristic: a004, a006, a010 and a015 remain in the normal lower caption area, with a006 reduced to fit. A conservative face rectangle that includes neck/clothing is not sufficient reason to move a caption to the top. Tweet translations use a real regular font face, a common left edge and source-baseline alignment; record the enlarged third-row exception where burned-in source dialogue occupies the space.

Font `file` paths in `fonts.toml` must be relative to the production project directory (`production/ginzawa/`). Machine-specific absolute paths are forbidden. Shared font assets and licenses live in the repository-level `fonts/` directory, referenced as `../../fonts/...`.

All event files `events-*.toml` use TOML array-of-tables syntax (`[[events]]`). Main captions refer to a reviewed segment with `id`. Do not duplicate text for main captions: edit `translation/work/segments.toml` using rajio segments commands. New overlapping labels use `id`, `start`, `end`, `text_ja`, `text_zh`, `supplemental = true`.

Each event can set `font_role` (keys from fonts.toml, including sans, serif, hand, brush, mono, ja, round, mincho, marker, casual, brush_title), `fontsize`, `x`, `y`, `align` (ASS 1–9), `color` / `outline_color` as RGB hex, `outline`, `shadow`, `bold`, `scale_x`, `scale_y`, `spacing`, `rotation`, `max_width`.

`line_advance` sets the distance between horizontal row anchors in full-resolution pixels. Rows share their width scale and move together; choose the advance and block position from actual visible ink gaps in the source Japanese rows. The source Japanese is burned in and is not moved.

User spacing correction: for ordinary static lower captions stacked above source Japanese, aim for approximately 24 px of visible separation at 1920×1080 (12 px at 960×540). Measure the rendered Chinese outline against the source ink, not just ASS anchors or font sizes. Existing source boxes are approximate screening aids; inspect local frames before applying changes. Small scene-dependent differences are acceptable, while unexplained large gaps should be corrected. Oversized dramatic text, motion, vertical text and inset annotations require their own composition; do not force the ordinary-caption gap onto them.

Ordinary face-avoidance layouts use centered top placement, never a left-side column. Inspect actual rendered libass ink, including shadows, and leave a visible margin at the frame edge. Negative anchor coordinates can be valid because font ascenders include invisible space; judge the rendered ink rather than the anchor value. Preserve scene-specific corner labels, panels and vertical speech separately.

User top-spacing correction: when a caption is placed at the top, keep it close to the upper edge with roughly 20 px of visible margin at 1920×1080, including outline/shadow. Existing margins of about 15–25 px can stay. Inspect composition and motion before adjusting; do not subtract the same anchor offset from every font or apply this to embedded labels and vertical captions.

Center ordinary dialogue by default. For a short object-related emphasis where both central upper and lower areas contain important content, a horizontal label may use nearby empty space after inspecting the whole event. Document the subject, competing content and selected space; this is not a generic left-column fallback. User-directed placements take precedence: c067 was moved from lower-left ground to top-center following user review, retaining its current size.

`line_breaks = [n1,n2,...]` provides manually chosen line lengths for horizontal performance layout only. Counts must sum to the reviewed Chinese character count after removing existing newlines; spaces count as characters. This changes no wording and does not alter SRT/rajio text. Use it for scene-specific arrangements near the original caption when preserving face visibility requires different wrapping. It cannot combine with vertical layout. Avoid automatically wrapping every caption by a fixed character count.

`effect`: none / fade / pop / slide / shake / pulse / typewriter / wipe / glow / distress. Parameters: `in_ms`, `out_ms`, `from_x`, `from_y`, `amplitude`, `period_ms`, `initial_scale`, `glow`, `char_ms`. Effects must be based on observed source behavior; do not apply animations just to embellish. Translation positions must not intersect source-caption bounding rectangles.

For observed mixed typefaces within one caption, `text_runs = [{length = 3, font_role = "brush"}, {length = 2, font_role = "mincho"}]` changes font family for successive characters without duplicating text. Lengths must sum to the Chinese text length (including newline); do not combine with editorial line breaks, vertical layout or typewriter. For irregular observed typewriter timing, `reveal_ms` supplies the reveal millisecond for each non-newline character; values must be nonnegative and sorted. Text stays in the translation work file.

`source_style`, `timing_status` and `limitations` describe scene-specific design decisions. `source_boxes` and `face_boxes` are lists of `[left,top,right,bottom]` rectangles in 1920×1080 source pixels. Keep separate rectangles for spatially separate lines or labels. Rendering does not generate audit reports or evidence links. Forge `audit-layout` checks actual rendered Chinese ink against these boxes to flag candidates for visual review.

The user permits Chinese to share an intentional face-covering effect when the original typography already does so. Judge the actual scene and emphasis, not a blanket geometric rule. Record `allow_face_overlap = true` and the scene-based reason in `limitations` for such exceptions. Ordinary unobstructed dialogue should still avoid newly covering faces; original Japanese text must remain visible in all cases.

For observed vertical speech, set `text_layout = "vertical"`. `x,y` anchor the top of the rightmost column. `column_chars` defaults to8; alternatively `vertical_columns` is an explicit list of character counts whose sum must match the text excluding newline. Columns advance right to left; `column_gap` (default1.25) and `row_gap` (default1.05) multiply fontsize. `vertical_rotate_punctuation` defaults to `…—～`. This changes glyph placement only; the editable Chinese wording remains in rajio. Fade/slide parameters apply to all characters together. Exact Japanese vertical glyph forms and balloons are approximated; report this limit.

Optional exact timing overrides `start`, `end` apply only in visual deliverables; prefer correcting active rajio data when possible. Final Japanese and Chinese plain tracks share these same corrected boundaries. Supplemental events may overlap normal dialogue, so ASS is the faithful editable delivery format.

ASS stores centiseconds. The builder floors source frame PTS to centiseconds rather than rounding up, so a cut at 402.235 starts at 402.23 and is visible on the 402.235 frame, without slipping to the following frame. SRT retains millisecond source timing. This is safe for the source's ~33 ms frame intervals.

Only a deliberately scrolling source caption may set `allow_offscreen = true`, with its reason in `limitations`. Set a large `max_width` for natural-width long scrolling text; otherwise the default width guard compresses it to fit.

For actual overlapping speech balloons, use exact `start`/`end` overrides and `allow_overlap = true`. Rajio's serialized dialogue may shorten them to maintain its work-file constraints, but final ASS/SRT should preserve the observed full visual lifetime. Explain overlap and cite boundary evidence. Audio-only lines should be labeled `timing_status = "audio-only"` and positioned separately.

`soft_shadow` adds a separate black layer beneath sharp foreground ink through the shared Forge shadow renderer: `x`, `y` offsets, `spread` outline, `blur` radius in full-resolution pixels, and `alpha` two-digit ASS transparency. It follows the same time, wrapping and movement. Foreground shadow/blur stay zero. Recompute this scene-specific field when changing fontsize.

`effect = "wipe"` provides observed continuous left-to-right ink reveal. Set `reveal_box=[left,top,right,bottom]` to the final translated ink envelope and `in_ms` to the observed completion time. `reveal_initial_width` optionally preserves the small visible portion at the first frame. The anchor stays fixed; ASS animates the clip rectangle, not whole-character alpha. Inspect the start, intermediate and final states to ensure the box includes outline/shadow.
